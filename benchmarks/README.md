# Benchmark Workspace

This directory contains the prototype benchmark harness that sits next to the core PTED package.

The goal is to keep the library in `src/` focused on PTED itself while this workspace grows into a separate compute and analysis layer for controlled two-sample experiments.

## Layout

- `benchmarks/datasets/gaussian.py` contains the synthetic 1D Gaussian benchmark family.
- `benchmarks/datasets/vision.py` also contains the lightweight 2x2 Gaussian image prototype used for laptop-scale testing.
- `benchmarks/datasets/vision.py` contains the planned MNIST and CIFAR10 class-split layout.
- `benchmarks/metrics.py` contains comparison methods that return sweep scores.
- `benchmarks/runners/gaussian.py` runs synthetic Gaussian sweeps.
- `benchmarks/runners/vision.py` defines the 2x2 Gaussian, MNIST/CIFAR class-split, and pair-blend sweep entry points.
- `benchmarks/plots.py` contains shared plotting helpers.
- `benchmarks/smoke.py` is a lightweight local sanity check for the benchmark paths.

## Current Status

- Synthetic Gaussian sweeps are runnable now.
- The 2x2 Gaussian image prototype is runnable on a laptop and is intended for quick end-to-end checks.
- KS is evaluated on the first principal component projection.
- FLD and FID are stored as raw scores and normalized during plotting so the null case maps to 1.
- MNIST and CIFAR10 are not downloaded automatically; only the layout for class-split experiments is in place.

## Planned Vision Tests

The future vision experiments will use a progressive class-mix schedule:

- severity `0.0` means both samples are mixed identically, which is the null case.
- severity near `1.0` means one sample is dominated by `class_a` while the other is dominated by `class_b`.
- the same sweep shape will be used for MNIST and CIFAR10 so their curves can be compared consistently.

Once local data or cached embeddings are available, the runner in `benchmarks/runners/vision.py` can be wired to a real loader without changing the experiment structure.

An additional contamination test is now scaffolded for MNIST/CIFAR10:

- `x` is sampled directly from the dataset pool.
- `y` is generated by selecting random sample pairs `(A, B)` and mixing them as
	`y = (1 - s) * A + s * B` with severity `s in [0, 0.5]`.
- `s = 0` corresponds to no contamination (`y = A`), and `s = 0.5` is maximal pair mixing.

This test is available via `run_vision_pair_blend_sweep`.

## Plotting

The plotting helpers in `benchmarks/plots.py` are intended to support two kinds of figures:

- sweep curves that show how each method responds as severity increases
- small prototype figures that show the 2x2 image means and their difference directly

These are kept outside the core PTED package so they can evolve into a separate analysis workflow later.

## Run Script

All top-level scripts use the same interface:

- `--config <yaml_path>`
- `--dry-run`

Top-level entry points:

- `benchmarks/run_gaussian.py` (default: `benchmarks/configs/gaussian_suite.yaml`)
- `benchmarks/run_vision_suite.py` (default: `benchmarks/configs/vision_suite.yaml`)
- `benchmarks/run_full_suite.py` (legacy alias; default: `benchmarks/configs/full_suite.yaml`)

`benchmarks/run_gaussian.py` orchestrates the 1D Gaussian challenge problems via `run_gaussian_sweep`.

`benchmarks/run_vision_suite.py` now orchestrates only vision benchmarks:

- 2x2 Gaussian image sweep
- MNIST/CIFAR10 class-split sweep
- MNIST/CIFAR10 pair-blend contamination sweep

For MNIST and CIFAR10, the vision config also supports `runs`, which splits each finite dataset into that many disjoint groups so repeated sweeps can produce medians and intervals across runs.

Use `benchmarks/load_vision_datasets.py --data-root <path>` to load MNIST and CIFAR10 from a directory and confirm the data is available before running the suite.

`benchmarks/run_full_suite.py` runs both the Gaussian and vision suite entry points against the same config file.

Examples:

```bash
python benchmarks/run_gaussian.py --dry-run
python benchmarks/run_vision_suite.py --dry-run
python benchmarks/run_full_suite.py --dry-run
python benchmarks/run_gaussian.py --config benchmarks/configs/gaussian_suite.yaml
python benchmarks/run_vision_suite.py --config benchmarks/configs/vision_suite.yaml
python benchmarks/run_full_suite.py --config benchmarks/configs/full_suite.yaml
```

You can disable any suite (`enabled: false`) or change sample counts, seeds, severities,
deviations, class pairs, datasets, and test cases directly in YAML.

The script writes per-suite CSVs/plots and an overall combined CSV in the configured output directory.

## Record Schema

Records are now intentionally minimal and score-centric:

- `method`
- `severity`
- task metadata fields (for example `deviation`, `seed`, `dataset`, `test_case`)
- `score`
- `raw_score`
